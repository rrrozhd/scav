---
name: find-missing-skill
description: Find and load a missing capability. Use when you lack a skill, agent or command for the task, or when the user asks you to find, add or load one from their plugins, including disabled ones, marketplaces, or GitHub. Use this instead of browsing ~/.claude/plugins or running `claude plugin` commands yourself.
---

`SCAV` means `uv run ${CLAUDE_PLUGIN_ROOT}/scripts/scav.py`. `REFRESH` means `claude plugin marketplace update scav && claude plugin update scav@scav`.

1. Run `SCAV find "<the need in a few plain words>" --catalogs --limit 8`. If nothing local fits, or the user asked for GitHub, add `--github`; it searches GitHub read-only for SKILL.md files and for plugins or `.mcp.json` files offering MCP servers or hooks, and takes about 20 seconds. Each line is: id, plugin, status, always-on tokens, description. Prefer words of 4 or more letters, because shorter words like `pdf` or `sql` are not matched. Ranking is by keyword overlap, so judge fit from the descriptions and read the file behind an id when two look alike. If nothing fits, say so and carry on without one.
2. Act on the status of the best fit:
   - `on` or `in-scav`: it is already loaded. Use it.
   - `off`: show its id, plugin, token cost and description in 2 lines. Wait for the user's yes. Then run `SCAV add --trial <id>` and REFRESH. A trial is not pinned, so the next `/scav` run drops it if it went unused. `/scav add` pins it for good.
   - `github ★N pushed DATE` (`gh:<owner>/<repo>:<path>`): show the repo, stars, last push, path and description. Low stars or an old push are reasons for caution, not refusal. Download nothing without an explicit yes. After a yes, run `SCAV fetch <owner>/<repo>`, which shallow-clones it into `~/.scav/github` and lists its skills, agents and commands. It never takes a fetched repo's hooks or MCP servers. Before adding, show the user any scripts in the picked skill's folder, since Claude may run them. Then continue from the `off` case with the `skill:gh-…` id that fetch printed (its status is `fetched`).
   - `github ★N pushed DATE, listing only` (an `mcp` or `hook` row): show the repo, path and the exact command or URL its description starts with. Scav never adds these: a hook or MCP server runs code as the user in every session. Stop there; the user can review the repo and install it as a plugin themselves.
   - `not installed` (`plugin:<name>@<marketplace>`): show the plugin, its marketplace and description. Install nothing without an explicit yes. After a yes, run `claude plugin install <name>@<marketplace>`, then `claude plugin disable <name>@<marketplace>`. Rerun step 1 and continue from the `off` case.
3. `add` prints the name each component loads under, `scav:<name>`, not its source plugin's name. Ignore REFRESH's "Restart to apply changes". Loaded components apply after the current response, so finish it and tell the user the component is available from their next message. If it isn't listed on the next message, ask the user to run `/reload-plugins`. `claude -p` only reloads that way.
