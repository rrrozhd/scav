# Scav

Plugin aggregator. Flow: `/scav`, which runs `scripts/scav.py profile`, then an in-session LLM screen, then `apply`, then `claude plugin disable` on the absorbed sources.

- Ingested components (`skills/`, `agents/`, `hooks/`, `.mcp.json`, `commands/*` except `scav.md`) are generated and gitignored. Never hand-edit them.
- Scav's own skills live in `skills-src/` (plugin.json `"skills": "./skills-src/"`, which adds to the default `skills/` and doesn't replace it; probed 2.1.296). `apply` prefixes ingested components named like them (`RESERVED`). `${CLAUDE_PLUGIN_ROOT}` expands in skill bodies.
- Mid-session find (`find`, `add --trial`, skill `find-missing-skill`; probed 2.1.303): when the skill listing is over budget, unused skills lose their description (only the name shows), while commands and used skills keep theirs. That is why the skill's name has to say what it does: `scav:find` was never picked, `scav:find-missing-skill` was. `claude -p` does not reload plugins mid-session unless it gets a `/reload-plugins` message.
- Versioning: `apply` and `restore` bump the patch number in `plugin.json` and `marketplace.json` so `claude plugin update scav@scav` picks up the new cache copy. Bump minor or major by hand for changes to Scav itself.
- Tests: `uv run --with pytest pytest -q tests`
- `skillOverrides` in settings did not hide plugin skills (probed on CLI 2.1.296 at user, project and `--settings` scope). That is why Scav copies components instead of writing a deny-list.
- `scav.py eval` wraps each component alone in a temp plugin and runs `claude plugin eval` on it (probed 2.1.296: every run gets a fresh config dir, so no user plugins or skills load). A case counts only if the component fired. Without the neutral `NUDGE` system line, sandboxed Sonnet fired 0 of 13 runs. The LLM judge sees only the response, never the prompt (probed 2.1.296), so each grader restates the request; history rows from before that fix lack `per_case` and are ignored. `context.add_dirs` only takes paths inside the case dir and is not in the model's cwd, so repo context is inlined instead: only the diff of an explicit commit range or a "review commit X". Verdicts use a side-by-side judge (`claude -p`, each with/without pair judged twice with the order swapped; the absolute rubric only carries the answer text) and one-sided 95% t bounds over distinct prompts (reruns average per prompt, they don't add n). Rows from before the side-by-side judge are ignored. Cases and calibration prompts must pass an LLM answerability screen (cached in ~/.scav/evals/answerable.json): 7 of 10 regex-clean openers still needed a repo, server or log. The baseline is a placebo skill, not vanilla: any loaded skill made answers longer and beat vanilla by +0.30, so each component runs alone (`--ablation none`) and is judged against the placebo's runs on the same prompts; firing is read by grader name because `withOnly` is only set with a no-plugin arm. Prune counts only after `eval --calibrate` passes on the same model and judge: the saboteur loses to the placebo and the placebo ties itself. The partial saboteur is reported as the power limit (n=10, one run: −0.47 [−1.01, +0.06]), so moderate effects stay inconclusive.
